# 01 · 快速开始

## 环境

| 工具 | 版本 | 用途 |
| --- | --- | --- |
| Cocos Creator | **3.8.6** | 打开工程、构建三端 |
| Node.js | ≥ 18 | Web 预览、脚本、关卡校验 |
| Xcode | ≥ 15 | iOS 真机 / 上架 |
| Android Studio | Iguana+，JDK 17 | Android 打包 |
| 微信开发者工具 | 最新稳定版 | 微信小游戏调试 / 上传 |

Cocos Creator 3.8.x 的工程格式与 3.8.6 一致；不要用 2.x 打开（会要求升级且大概率丢引用）。

---

## 一、打开工程

1. 打开 **Cocos Dashboard** → 项目 → **添加**。
2. 选择本目录（包含 `project.json` 的 `ArrowClear/`）。
3. 双击项目，等待首次资源导入（会为 `assets/` 下的 png / ttf / scene 生成 `.meta`，属正常现象）。
4. 在 **资源管理器** 里打开 `assets/scenes/main.scene`。
5. 点击右上角 ▶（浏览器预览）。

首次打开建议按这个顺序确认：

- [ ] 场景里能看到 `Canvas → Camera + GameRoot`
- [ ] `GameRoot` 节点上挂着 `GameRoot` 组件（脚本）
- [ ] 项目设置 → 项目数据 → 设计分辨率 **720 × 1280**，勾选 **Fit Width**
- [ ] 项目设置 → 项目数据 → 屏幕方向 **Portrait**
- [ ] 预览后能看到首页（Logo + 吉祥物 + 开始游戏）

> 代码在 `onLoad` 里会再执行一次
> `view.setDesignResolutionSize(720, 1280, ResolutionPolicy.FIXED_WIDTH)`，
> 所以即使设计分辨率被改坏，运行时也会被纠正。

### 如果场景打不开 / GameRoot 丢失

Cocos 的场景是 JSON 序列化文件，跨版本偶发引用问题。30 秒兜底：

1. 新建场景，保存为 `assets/scenes/main.scene`（覆盖）。
2. 场景里默认有 `Canvas`（含 Camera）。
3. 在 Canvas 下新建空节点，命名 `GameRoot`。
4. 把 `assets/scripts/cocos/GameRoot.ts` 拖到该节点上。
5. 保存，运行。

整个游戏的 UI、棋盘、弹窗都是 `GameRoot` 在运行时用代码创建的，场景里不需要摆任何东西。
（这也是为什么场景文件故意做得极小：只有 11 个序列化对象。）

## 二、Web 预览（不依赖 Cocos）

```bash
npm install
npm run web
# → http://localhost:4173
```

- 单文件构建：`npm run build:web` → `dist/web/`（index.html + main.js + style.css + fonts）
- 类型检查：`npm run check`
- 关卡校验：`npm run test:levels`（会打印 60 关的箭头数、填充率、初始可飞数量、限时）

Web 版与 Cocos 版共用 `assets/scripts/core`，规则完全一致，但表现层是两套：

| | Web | Cocos |
| --- | --- | --- |
| 渲染 | Canvas 2D | `Graphics` + `Sprite` |
| UI | DOM + CSS | 代码构建的 Node / Label |
| 输入 | PointerEvent | `TOUCH_END` + `UITransform.convertToNodeSpaceAR` |
| 存档 | localStorage | `sys.localStorage` |

用途：快速改玩法、看数值、录商店演示；正式发版以 Cocos 工程为准。

## 三、构建三端（GUI）

菜单 **项目 → 构建发布**，新建构建任务：

| 平台 | 选项 | 产物 |
| --- | --- | --- |
| Web Mobile | 资源服务器地址留空 | `build/web-mobile/` |
| iOS | Bundle ID、Team、竖屏 | `build/ios/proj/`（Xcode 工程） |
| Android | Bundle ID、API Level 35、AAB | `build/android/proj/` |
| 微信小游戏 | AppID、设备方向 portrait | `build/wechatgame/` |

命令行构建（需要已安装编辑器，路径按实际安装位置调整）：

```bash
/Applications/Cocos/Creator/3.8.6/CocosCreator.app/Contents/MacOS/CocosCreator \
  --project "$(pwd)" \
  --build "platform=web-mobile;debug=false"
```

平台名：`web-mobile` / `ios` / `android` / `wechatgame`。

## 四、常见问题

**页面黑屏 / 只有背景**
`GameRoot` 没挂上，或场景里 Canvas 的 Camera 丢了。按上面的兜底方案重建。

**文字显示成方块或空白**
Cocos 用的是 `assets/resources/fonts/ZCOOLKuaiLe-Regular.ttf`（子集字体，43KB）。
新增了 UI 文案但没重新子集化时，新字会缺字。执行：

```bash
python3 tools/subset_font.py     # 需要 /tmp/fontenv 里的 fonttools，见 docs/06
```

**图标 / 吉祥物不显示**
资源必须位于 `assets/resources/art/` 下，代码按 `art/icons/gear/spriteFrame` 这类路径加载。
检查控制台是否有 `[assets] missing sprite ...`。

**棋盘超出屏幕**
棋盘按「可用宽度 / 列数、可用高度 / 行数」取小值计算格宽，正常不会溢出。
如果自定义了关卡行列数，确认 `specFor()` 里 `cols/rows` 与手机长宽比匹配（建议 0.55~0.75）。

**微信小游戏包体超 4MB**
当前代码 + 资源远小于 1MB；如果后续加了大量音频/大图，把 `assets/resources/art`、`audio`
拆到分包，或用远程资源（构建面板里勾选「资源服务器地址」）。

## 五、改关卡 / 调皮数值

- 难度曲线：`assets/scripts/core/levels.ts` → `specFor(id)`
  （章节棋盘尺寸、目标箭头数、路径长度、初始可飞数量、随机种子）
- 星级 / 金币：`GameRoot.ts` 的 `win()` 与 `useHint()`
- 限时：`levelgen.ts` 里 `level.timeLimit` 的公式


改完跑一次 `npm run test:levels`，确认 60 关仍然全部可解。
